别把 `OTA_Info.FileLen[]` 里已有的这个数直接当成固件长度。

### 第二步：4b-2b —— 收固件写 W25Q64 并触发搬运

**协议**（服务器先发长度头，MCU 才知道该收多少、能校验）：

```
MCU   → 服务器   "OTA_REQ\n"
服务器 → MCU     "OTA <真实长度> <CRC16>\n" + <真实长度 字节固件>
```

- `真实长度` = 固件 bin 实际字节数，**不是** Xmodem 128 字节对齐后的值
  （A 区 bin 13000 → Xmodem 口径 13056，`boot.c` 存进 `FileLen[]` 的是后者）
- `CRC16` = CRC-16/XMODEM（初值 0x0000、多项式 0x1021），覆盖 `\n` 之后的那 `真实长度` 字节
- 服务器收到 `PING`（`[t]` 4b-2a）时仍按裸发模式、不带头 —— 让 `[t]` 继续能当回归测试用

#### ⚠️ 落盘位置是块 0 / FileLen[0]，不是块 1

本文档早期版本写的是 `FileLen[1]` + `W25Q64_Erase64K(1)` —— **那是错的**。
代码里 OTA 路径用的是块 0：

| 证据 | 位置 |
|---|---|
| OTA 分支置 `UpDataA.W25Q64_BlockNum = 0` | `boot.c:25` |
| 搬运读 `FileLen[UpDataA.W25Q64_BlockNum]` → `FileLen[0]` | `main.c:332` |
| 搬运源地址 = `BlockNum * 64 * 1024` → 块 0 | `main.c:338` |
| 只有 `BlockNum == 0` 才清 `OTA_Flag` | `main.c:346` |

照错的写会「写块 1、读块 0」，搬进 A 区的是垃圾。块 1~9 是命令 5/6 的用户固件槽位。

#### 实现时的三个非显然决定

1. **擦除必须在发 `OTA_REQ` 之前**。64KB 块擦典型 150ms、最坏 1~2s，
   而接收缓冲 512 字节只装得下 115200 下的 44ms 数据 —— 擦除期间线上来的全被静默丢掉
   （`s_rxOverflow` 只写不读；本次已加 `G4_RxOverflow()` 把它变成可打印）。
   擦除不依赖 `len`，所以可以提前做。
2. **`Xmodem_CRC16` 拆成增量式**。原来把初值 `0x0000` 写死在函数体里，没法
   "每收一页算一次再续算" —— 那样得到的是最后一页的 CRC。现在 `Xmodem_CRC16()`
   只剩一行 `Xmodem_CRC16_Update(0x0000, ...)`，行为不变。
   已用 PC 上的 gcc 抽出 boot.c 里的**真实函数**跑真实固件验证：整段 / 每 256 字节续算 /
   逐字节续算三种方式结果一致（`0xDB6E`），且与 `scripts/crc16.py`、服务器发送值都相等。
3. **不动 U1 事件环指针**。下载期间主循环不消费事件环，这段时间敲的字符会在结束后被当命令
   执行（敲个 `1` 就是"擦除A区"）。试过"把 `In` 拉平到 `Out`"——行不通：`URxDataIn` 指向
   正在填充的槽位、其 `start` 已被中断设成下一次 DMA 的目标，而 `main.c` 处理完事件后
   **无条件** `URxDataOut++`，硬拉平会让那个 `++` 落到陈旧槽位（`end` 是上轮残留 →
   `datalen` 垃圾），反而更危险。改为明确打印提示"下载期间别敲字符"——
   与命令 2/5 的 Xmodem 窗口同类处理（`usart.h` 开头记过同类问题）。

#### 刻意没做的

- **`G4_RxDrop` 逐字节的 O(n) 批量消费重构**：4b-2a 已实测 13000 字节零误差，当前吞吐够用。
  留作独立一步，免得把"协议改动"和"接收路径重构"混在一起。
- **服务器 ACK 流控**：那是把 `--delay` 降到 0 的前提。

**`--delay` 不能去掉的原因**：`G4_PayloadGet` 每取 1 字节就 `G4_RxDrop(1)`，而 `G4_RxDrop`
要搬 `s_rxLen-1` 字节 —— **缓冲越满、单字节成本越高**，满速下会自锁。
`--delay 0.05` 是真正的安全余量，不是随手写的。

## 必须遵守的约束（都是踩过坑换来的）

1. **一次只改一个变量** —— 曾同时改两处导致根因永远无法归因。
2. **改完 BootLoader 代码必须量容量**：`python _tools/verify_repartition.py`
   （链接成功 ≠ 装得下，链接器只按 IROM 的 start/size 检查）
3. **源码编码 = 串口输出编码**：ARMCC 原样透传字节。源码 UTF-8+BOM，
   串口发 UTF-8，**上位机终端必须设 UTF-8**。
4. **`.uvprojx` 里 `<OCR_RVCT4>` 才是生效的 IROM1**，`<IROM>` 那个改它没用。
5. **Python 写补丁脚本的转义规则**（今天踩了五六次）：
   - 要 C 里的 `\r\n` → Python 里写 `\\r\\n`
   - 要 C 里的 `\\x` → Python 里写 `\\\\x`
   - 制表符 `\t` 直接写
   - **工程里的 .c 是 CRLF**，多行常量匹配前必须归一化行尾
6. **丢失数据的形状区分病因**：连续整段丢 = 还没开始听；零散丢 = 听不过来。
7. **别在日志里找不到就断定代码没执行** —— 先确认日志覆盖范围
   （`G4_Cmd` 打日志，`G4_SendCmd` 不打）。
